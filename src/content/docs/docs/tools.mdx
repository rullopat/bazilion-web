Every turn gets the same tools, whatever started it: web or CLI chat, a follow-up, Telegram, a
scheduled trigger or an inbox wake. Some depend on you having started the turn: `agent_create`,
which a schedule or a teammate's message never gets, `ask_user` and `secret_request`
([questions](/docs/questions/)) and dangerous-command approval, which is denied when nobody can
answer. A [helper](#helpers) gets the Agent's tools except the helper tools and the ones that ask
you something.

## Built-in tools

| Tools | What they do |
| --- | --- |
| `bash`, `read`, `edit`, `write`, `grep`, `find`, `ls`, `apply_patch` | Work in the Team directory, on the host or in Docker ([coding](/docs/coding-environment/)) |
| `job_list`, `job_output`, `job_input`, `job_stop` | Commands started with `bash` in the background: a dev server, a watcher, a long build ([background jobs](/docs/coding-environment/#background-jobs)) |
| `memory_write`, `memory_read`, `memory_search`, `memory_list` | The Team's shared Markdown memory |
| `recall` | Searches and rereads the conversation's messages a summary replaced, and the Agent's other conversations ([compact and context](/docs/conversations/#compact-and-context)) |
| `home_read`, `home_write`, `home_list`, `bootstrap_done` | The Agent's own documents |
| `user_md_get`, `user_md_write` | The Team's USER.md |
| `send_message`, `read_inbox`, `wait_for_reply` | The mailbox, within [Team Policy](/docs/concepts/#team-policy); `to` is a teammate's id or name. A quiet message (`wake: false`) waits without starting a turn; `wait_for_reply` can wait for several replies |
| `agent_create` | Adds an Agent to its own Team when you ask, in a turn you started ([Agents](/docs/concepts/#agents)) |
| `schedule_add`, `schedule_list`, `schedule_remove` | Schedules the Agent sets itself: once, every few minutes or a cron expression, in the conversation it was set in; it removes only its own ([schedules](/docs/operations/#schedules)) |
| `secret_request`, `secret_list` | Asks you for a secret by name, in a masked field, and lists its secrets' names; the values never reach it ([secrets](/docs/questions/#secrets-an-agent-asks-for)) |
| `helper_start`, `helper_wait`, `helper_stop` | [Helpers](#helpers): runs of the same Agent on separate tasks at once |
| `view_image`, `pdf_read` | Looks at pictures (files, the web, saved results) and reads PDFs page by page ([files in and out](#files-in-and-out)) |
| `web_fetch`, `web_search` | [Web research](#web-research); `web_fetch` takes request headers, and fills in a secret written `{{secret:NAME}}` only for that secret's hosts |
| `browser_*`, `browser_use` | The [managed browser](#managed-browser); `browser_use` moves the conversation to [your Chrome or back](#its-own-or-yours-per-conversation) |
| `mcp__<server>__<tool>`, `tool_search` | Tools from [MCP servers](#mcp-servers), loaded with `tool_search` when a task needs them ([tools found when needed](#tools-found-when-needed)) |
| `codemode` | Runs one short script that calls several of the Agent's tools and hands back only what matters ([scripts](#scripts)) |
| `image_generate` | [Image generation](#image-generation), when a model is set |
| `video_generate`, `audio_generate` | [Video and sound](#video-and-sound), when a model is set |
| `speak`, `transcribe` | [Speech](#speech): reads text out in a voice; turns a recording of the workspace into timed text |
| `progress`, `screen`, `theme`, `canvas` | The Agent in the workspace: a progress card updated in place, opening a panel tab, view or sheet in the tabs on its conversation, the theme, and a small HTML or SVG page in the chat ([web interface](/docs/web-interface/#the-conversation)) |
| `deliver_file` | Saves a workspace file as a [result](/docs/results/), or shows a saved one again |
| `ask_user` | Asks you questions, or to do something only you can do, when someone is watching ([questions](/docs/questions/)) |

While a tool runs, its output streams into the chat; see
[live tool output](/docs/coding-review/#live-tool-output).

## Setting the tools

Web search, the page reader, the browser, how commands run and how long a chain of messages
between Agents may get are set on one page: **Setup → Tools** (`/config/tools`). Each has a card
that says what is in effect now, and what a choice would meet on this machine before you save
it: a key that is missing, or whether Docker has the image. A setting that only matters with
another choice appears with it.

![Setup, Tools: the Web search card with its five choices, a saved Brave key and the SearXNG address, the Web pages card and the Browser card with its switch and two choices.](/screenshots/tools.webp)

A card is saved whole. Every value is checked first, and when one is refused nothing of the card
is stored. The same settings from a terminal, one or several together:

```sh
bazilion config list                                # every setting, and what is in effect
bazilion config set BAZILION_WEB_SEARCH_ROUTE brave
bazilion config set BROWSER_ATTACH=true BROWSER_ATTACH_URL=http://127.0.0.1:9222
```

A setting that the daemon's own environment carries wins over the stored one: its card shows the
value in effect and leaves it alone.

## Web research

- `web_search` finds sources. The daemon runs the search, so backend URLs and keys never reach
  the Agent. It takes filters: how recent (`freshness`, or `after` and `before`), `sites` and
  `exclude_sites`, a `country` and a `language`. Each backend applies the ones it supports, and
  the result names the rest. A search repeated in a turn is not sent again.
- `web_fetch` reads a page as Markdown. It refuses private and loopback addresses, also after
  redirects, and caches pages for 15 minutes. With `FIRECRAWL_API_KEY` set, a page whose text comes
  out nearly empty is fetched again through Firecrawl. A page longer than what it returns is saved
  whole with the Agent's uploads, and the Agent is told where to read the rest.

`BAZILION_WEB_SEARCH_ROUTE` picks the search backend: the **Web search** card under
[**Setup → Tools**](#setting-the-tools), or `bazilion config set BAZILION_WEB_SEARCH_ROUTE <value>`:

| Value | Backend |
| --- | --- |
| `auto` (default) | The first that is set up: Brave (`BRAVE_API_KEY`), SearXNG (`SEARXNG_URL`), Tavily (`TAVILY_API_KEY`), Exa (`EXA_API_KEY`), then `native` |
| `brave` | The Brave Search API with `BRAVE_API_KEY` |
| `searxng` | Your SearXNG instance at `SEARXNG_URL`, with JSON output enabled |
| `tavily` | The Tavily Search API with `TAVILY_API_KEY` |
| `exa` | The Exa Search API with `EXA_API_KEY` |
| `native` | The search built into the Agent's own model: OpenAI models with `OPENAI_API_KEY`, or ChatGPT models with the ChatGPT login. Other models get no `web_search` |
| `off` | No `web_search` tool |

A backend that is chosen but not configured leaves Agents without `web_search`; nothing falls
back to another one. A query has at most 512 characters and returns up to 10 results. `web_fetch`
reads at most 3 MiB of a page and returns 20,000 characters by default.

## Managed browser

Each Agent has its own browser: the Chrome, Brave, Edge or Chromium installed on the machine,
running on a persistent profile, so cookies and logins carry over between turns. Bazilion looks in
the usual install places on Linux and in `/Applications` and `~/Applications` on macOS. When no
browser is installed, the daemon downloads Chromium once (a few hundred MB), at startup or at the
first browser action; `PLAYWRIGHT_SKIP_BROWSER_DOWNLOAD=1` in the daemon's environment turns that
off. The Agent reads
pages as accessibility snapshots with refs such as `[ref=e5]` and acts on them with
`browser_navigate`, `browser_snapshot`, `browser_click`, `browser_type`, `browser_fill_form`,
`browser_select`, `browser_hover`, `browser_press_key`, `browser_go_back`, `browser_tabs`,
`browser_take_screenshot` (of the page or one element), `browser_console` and `browser_network`.
To check a web app it also has `browser_errors` (console errors and uncaught page errors),
`browser_text` (the readable text), `browser_wait` (until a text or an element shows),
`browser_emulate` (a phone, dark mode, a locale, a time zone) and `browser_pdf`. A PDF, and a file
a page downloads in the Agent's own browser, are saved with its uploads.

The browser starts at the Agent's first browser action and stops after `BROWSER_IDLE_MS` of
inactivity. Its settings are on the **Browser** card under
[**Setup → Tools**](#setting-the-tools), the rarer ones under **More settings**:

| Key | Default | |
| --- | --- | --- |
| `BROWSER_ENABLED` | `true` | Give Agent turns the browser tools |
| `BROWSER_EXECUTABLE_PATH` | discovery | Browser binary; otherwise the first installed Chrome, Brave, Edge or Chromium, then the downloaded Chromium |
| `BROWSER_ATTACH` | `false` | Which browser, unless you say otherwise: `true` starts every conversation in [your running browser](#your-running-browser) |
| `BROWSER_ATTACH_URL` | found | DevTools address of the running browser, such as `http://127.0.0.1:9222` |
| `BROWSER_HEADLESS` | `true` | `false` opens a visible window; not used with a running browser |
| `BROWSER_ALLOW_PRIVATE_NETWORK` | `false` | Turn the SSRF proxy off; local development only |
| `BROWSER_IDLE_MS` | `900000` | Stop a browser after 15 minutes idle |
| `BROWSER_MAX_SESSIONS` | `4` | Browsers running at once |

In an Agent's own browser, all traffic goes through a proxy in the daemon that refuses loopback, private and
link-local addresses. Downloads are refused and WebRTC and QUIC are off, so nothing goes around the
proxy.

The profile lives in `~/.bazilion/browsers/<agent-id>/`. It holds the Agent's cookies and logins,
is never mounted into the Docker sandbox and is left out of backups. Manage it under **Browser**
in the Agent's side panel or:

```sh
bazilion agent browser status <agent>   # never starts the browser
bazilion agent browser stop <agent>     # keeps the profile
bazilion agent browser reset <agent>    # deletes the profile; --yes skips the prompt
```

Archiving an Agent stops its browser; deleting it deletes the profile. Sites may still block the
browser or show CAPTCHAs and logins; the Agent is told to stop and tell you. To sign an Agent in to
a site, set `BROWSER_HEADLESS=false`, let the Agent open the site and sign in in the window that
appears; the login stays in that Agent's profile.

### Its own or yours, per conversation

**Which browser, unless you say otherwise** on the **Browser** card is where every conversation
starts: the Agent's own browser unless you change it. In a conversation, ask the Agent to "use my
Chrome" or "use your own browser": it switches with `browser_use`, for the rest of that
conversation, later turns included. Other conversations keep the default.

- Moving to your Chrome asks you first, in the conversation and on Telegram, because on every site
  you are signed in to the Agent acts as you. **Allow** lasts for the conversation. Where nobody
  can answer (a schedule, a teammate's message) the move is refused. With your Chrome as the
  default, nothing is asked.
- Going back to its own browser needs nothing. A helper starts in the browser of the conversation
  that started it.
- An Agent works in one browser at a time: switching closes the other one, and its profile and
  logins stay. **Browser** in the Agent's side panel names the one it is using.

### Your running browser

In your running browser, Agents work in the Chrome or Chromium you have open, signed in wherever
you are: in a conversation that moved there, or in every conversation with `BROWSER_ATTACH=true`.

1. In Chrome 144 or later, open `chrome://inspect/#remote-debugging` and allow remote debugging.
2. Ask the Agent to use your Chrome, or choose **My running Chrome** on the **Browser** card under
   **Setup → Tools** (`bazilion config set BROWSER_ATTACH true`) to make it the default.
3. When the Agent reaches your Chrome, Chrome asks whether to allow the connection. Allow it within
   a minute.

For another Chromium-family browser, or a profile outside the default place, start it with
`--remote-debugging-port=9222 --user-data-dir=<directory>` and set
`BROWSER_ATTACH_URL=http://127.0.0.1:9222`.

- An Agent sees and drives only the tabs it opens and the tabs those open. Your own tabs are never
  listed, read or closed.
- All Agents share one connection. When the last Agent's session ends, its tabs close, the
  connection is dropped and your browser keeps running; the next browser action asks Chrome again.
- An Agent's saved profile is left as it is for when you turn the mode off.

<Aside type="caution">
In your running browser the Agent acts as you on every site you are signed in to. It is told to
post, send, buy, delete or change settings only when you asked for exactly that. The daemon's proxy
cannot cover this mode: each request of an Agent's tab is checked against the same rules instead,
which misses a service worker's requests, the first request of a tab that a page opened and a host
name whose address changes after the check. Downloads are refused in the Agent's tabs only. Use the
mode with Agents and tasks you trust.
</Aside>

<Aside type="caution">
`BROWSER_ALLOW_PRIVATE_NETWORK=true` lets pages reach your local network and `file:` URLs. Use it
only for local development.
</Aside>

## MCP servers

Tools from Model Context Protocol servers reach every turn as `mcp__<server>__<tool>`.

### Tools found when needed

An Agent is not given every MCP tool up front. Its prompt lists each connection with how many
tools it has, and the Agent loads the tools a task needs with `tool_search`, from their names and
descriptions; they stay loaded for the rest of the conversation. A [script](#scripts) can call any
of them, loaded or not. So many connections with many tools no longer fill the model's window
before the conversation starts.

### Common connections

**Common connections** on **Setup → MCP** lists four third-party servers for the services a
business Team works in. Each runs on your computer, and connecting one asks only for what it needs:

| Connection | What Agents can do | Needs |
| --- | --- | --- |
| Microsoft 365 | Outlook mail and calendar, OneDrive, Excel; Teams and SharePoint with a work account | Nothing to paste: ask an Agent to sign in, and it gives a link and a code |
| Google Workspace | Gmail, Calendar, Drive, Docs, Sheets | `uv`, and an OAuth client of your own from Google Cloud |
| Slack | Read channels, threads and search; post when you allow it | A user token (`xoxp-…`) |
| Notion | Pages and databases shared with it | An integration secret (`ntn_…`) |

```sh
bazilion mcp presets
bazilion mcp add notion --preset notion --env NOTION_TOKEN=ntn_…
```

### Tools that ask first

A tool whose name says it sends, posts, replies, shares, creates, updates, moves, deletes or
uploads something asks you before each call, as a risky shell command does: in the conversation,
in Telegram after 30 seconds, and in Attention. In a turn nobody can answer (a schedule, a
teammate's message) it is refused, so nothing goes out unseen. After **Test** you can tick or
untick single tools; every other tool, one the server adds later too, keeps following the rule.
The rule reads names only, so look at the list after **Test**.

### Adding any server

Servers are configured once for the whole installation, on `/config/mcp` or with the CLI:

```sh
bazilion mcp add files --command npx --args "-y @modelcontextprotocol/server-filesystem /my/project"
bazilion mcp add docs --transport http --url https://mcp.example.com/mcp --token <bearer>
bazilion mcp list
bazilion mcp test <server-id>      # connect afresh and list the tools
bazilion mcp disable <server-id>   # or enable
bazilion mcp rm <server-id>
```

- **stdio** servers run as daemon child processes. They get the daemon's environment with your
  provider keys, but never Bazilion's own credentials, plus variables of their own (a token, a
  client id: `--env`, or **Variables** on the server's row). Those are stored encrypted and given
  to that server only, never to an Agent's environment. Treat these servers as trusted local
  programs.
- **http** servers use Streamable HTTP. The bearer token is stored encrypted and redirects are
  refused. A token passed with `--token` can land in your shell history; the web page avoids that.

A server starts on first use and is shared by all turns. One that fails to start or to list its
tools within 10 seconds is skipped for that turn; `bazilion mcp test` shows why. Calls time out
after 60 seconds and are never retried. Files in a tool's result reach the Agent: pictures as
pictures, text files as text, and others, such as a PDF, saved with its uploads under `mcp/`
with their path given. Only tools are supported: no MCP resources, prompts, sampling or automatic
OAuth sign-in.

## Scripts

With `codemode` an Agent writes one short JavaScript script that calls several of its tools, MCP
tools included, and hands back only what matters, instead of one round trip through the model per
call. Scripts run in a sandbox with no network, files or timers of their own: they reach the world
only through the Agent's tools.

- The conversation shows **Ran a script**, with the calls it made (✓ for each that worked) and the
  files they saved.
- A dangerous command or an MCP tool that asks first still waits for you inside a script.
  Questions to you (`ask_user`, secret requests) and `browser_use` are never made from one.
- Credentials are taken out of what each call returns, as for any tool result.
- Code Mode adds about 840 tokens to each request. A script's long output is cut, and the whole of
  it written to a file in the system's temporary folder, which a Docker turn cannot read.

## Helpers

An Agent can split its work: `helper_start` runs another turn of the same Agent on one
self-contained task, in a conversation of its own, beside its own turn, and several can run at
once. `helper_wait` waits for their answers and shows what each is doing while it waits;
`helper_stop` ends one. A helper's pages and output stay out of the Agent's context, which gets
only the answer. A helper cannot start helpers of its own or ask you anything, and dangerous
commands are refused in it, as in any turn nobody watches. An answer that comes after the
Agent's turn ended starts a turn of its own; stopping the Agent's turn stops its helpers.

The Agent's **Helpers** sheet lists them with **Stop** and **Open** (its conversation), and the
side panel counts the ones working. From a terminal:

```sh
bazilion agent helpers <agent>                 # running first, then the ones that ended
bazilion agent helpers <agent> --stop all      # or --stop <helper-id>
```

Helpers live in the daemon's memory: a restart stops them, and their conversations stay. Usage
counts each helper's conversation under its Agent. They share the Agent's browser.

## Image generation

`image_generate` creates an image from a prompt and saves it as a [result](/docs/results/). It is
off until you pick a model with `BAZILION_IMAGE_MODEL`: under **Images** on **Setup → Models**
(`/config`), where a choice whose account is missing has a button that connects it, or with
`bazilion config set BAZILION_IMAGE_MODEL <value>`:

| Value | Account |
| --- | --- |
| `off` (default) | No `image_generate` tool |
| `openai-codex:gpt-image-2` | Your ChatGPT login; uses the subscription |
| `openai:gpt-image-2` | `OPENAI_API_KEY`; billed per image by OpenAI |
| `openrouter:google/gemini-3.1-flash-image` | `OPENROUTER_API_KEY`; billed by OpenRouter |
| `openrouter:openai/gpt-image-2` | `OPENROUTER_API_KEY`; billed by OpenRouter |

The Agent can give pictures to start from (`references`): files in the workspace or its uploads,
for an edit, a variation or a style. With `background: true` the call answers at once and the
Agent is woken to show the picture when it is ready.

At most four calls per turn, each waiting up to 180 seconds. Nothing is retried, and a call that
failed after the request was sent may still have been billed. Set spending limits in the
provider's own account.

## Video and sound

`video_generate` makes a short clip with sound, from a prompt or from a picture as its first
frame; `audio_generate` makes a song, a jingle, background music or a sound effect. What they make
is saved as a [result](/docs/results/), plays in the chat and under **Files**, and goes to a bound
Agent's Telegram topic. Each is off until you choose a model on **Setup → Models** (the **Video**
and **Music and sound** cards) or with `bazilion config set`:

| Setting | Value | Account |
| --- | --- | --- |
| `BAZILION_VIDEO_MODEL` | `xai:grok-imagine-video-1.5` | `XAI_API_KEY`; 1 to 15 seconds |
| | `google:gemini-omni-1.2-flash` | `GEMINI_API_KEY`; 3 to 15 seconds, landscape or portrait |
| | `minimax:MiniMax-H3` | `MINIMAX_API_KEY`; 4 to 15 seconds |
| `BAZILION_AUDIO_MODEL` | `elevenlabs:music_v2_5` | `ELEVENLABS_API_KEY`; music and sound effects |
| | `google:lyria-3.5` | `GEMINI_API_KEY`; music, with its lyrics |

A video always runs in the background: the Agent is woken in the same conversation when it is
saved, or with the provider's reason. Music and sound wait, or run in the background.
**ElevenLabs** is under **Add a provider** as an account for media only, with no chat models.
OpenAI's Sora and Veo on the Gemini API are not offered: their providers shut them down.

## Speech

A **Speech** model reads text out: `speak` (the audio is saved and sent to Telegram as a voice
note), the speaker under each Agent message in the web chat, and voice replies to the voice notes
you send on Telegram. Choose it and its voice on the **Speech** card, which lists the provider's
voices with a sample, or with `bazilion config set BAZILION_SPEECH_MODEL …` and
`bazilion speech voices`:

| `BAZILION_SPEECH_MODEL` | Account |
| --- | --- |
| `elevenlabs:eleven_v4` | `ELEVENLABS_API_KEY` |
| `google:gemini-3.8-flash-tts` | `GEMINI_API_KEY` (WAV: Telegram shows it as a file) |
| `xai:tts` | `XAI_API_KEY` |
| `minimax:speech-2.8-hd` | `MINIMAX_API_KEY` |

A **Transcription** model turns speech into words: voice notes and audio you send (before the
turn), dictation with the microphone beside the paperclip (on `https://` or this computer), and
`transcribe`, which gives a recording's lines with their times where the model gives them.
`BAZILION_TRANSCRIPTION_MODEL` is `openai:gpt-transcribe`, `google:gemini-3.5-transcribe`,
`xai:grok-voice-transcribe-2.0`, `groq:whisper-large-v3-turbo`,
`mistral:voxtral-mini-transcribe-3` or `elevenlabs:scribe_v3`, each on its provider's key and up
to the largest file it takes.

## Files in and out

**In.** Attach files in the web composer (button, paste or drag and drop), in Telegram, or from
the CLI. Images reach the model as images; any other file is saved to the Agent's `uploads/`
directory and the Agent gets its path, and reads a PDF with `pdf_read`, page by page (a scanned page has no
text, and there is no OCR). Video is stored as a file. Audio, such as a Telegram voice note, is
stored too; with a model chosen under **Transcription** on **Setup → Models**
([speech](#speech)) it is also turned into words before the turn, which the Agent gets with the
file's path. Transcription is off by default.

`view_image` shows the model several pictures at once: files in the workspace or uploads,
pictures on the web and the Agent's saved results, PNG, JPEG, GIF or WebP. A model that takes no
images is told so instead.

```sh
bazilion agent chat <agent> --message "Describe this screenshot" --image ./screenshot.png
bazilion agent chat <agent> --message "Summarise this report" --file ./report.pdf
```

**Out.** `deliver_file` saves a workspace file (up to 25 MiB) as a [result](/docs/results/): a
download card in the web chat, a document in the Agent's Telegram topic, and a file in the current
directory for `bazilion agent chat`. Screenshots and other tool images show inline in the chat and
as Telegram photos.
